- **The web UI can sign in through an authenticating reverse proxy.** With `graphql.proxy_auth_header` naming the header a proxy such as Authelia or Authentik sets (`Remote-User`), and `graphql.proxy_auth_from` the addresses that proxy connects from, the web UI signs in the account the header names without asking for a password. The header is read only on web UI pages and the MCP consent page, ignored from any other address and when it carries more than one value, and an account the server lacks is refused, not created. The proxy must cover those pages and strip the header from incoming requests; [Behind an authenticating proxy](docs/guide/headless-server.md#behind-an-authenticating-proxy) lists the exact paths to exempt, with Caddy and Traefik examples. A session through the proxy has no refresh cookie and is derived again from the header on each page load, so it lasts no longer than the proxy's say-so, and a browser whose proxy sign-in changes is handed to the new account. Turning proxy mode on does not end web sessions signed in with a password before it; the guide says how to. A header from the proxy that names no one account, or an account the server lacks, signs the browser out rather than leaving it on the session it had. It is on only with both settings set; the server refuses to start with one alone, with an entry it cannot parse, or with a range covering every address, and logs the header and addresses it believes when it is on. The Subsonic API, GraphQL, MCP and kōan's apps keep kōan's own sign-in. This is Navidrome's `ND_REVERSEPROXYUSERHEADER`.
