kōan

It's a music player. Designed for both local and remote collections (subsonic/navidrome). Remote works with a fairly aggressive local cache. It is super fast and handles 1TB+ libraries with ease and has all the things you'd want like gapless, queue management, "bit-perfect" (so much as the audio stack allows), combined search...etc. Built from 25 years of experience messing about with music and being annoyed with pretty much everything and wanting my dream application. There are some organisational features such as file renaming, which is compatible with fb2k syntax, and I plan to add a decent well thought out tagger once I have pondered the UX more.

Originally built as a Rust TUI and core, I've now added a beautiful macOS SwiftUI app (no Electron) that uses FFI to bridge to the rust. It's fast, it's pretty, it has these lush transitions, and the point is to do all the basics properly and well before adding features, I'm really proud of it. The UX is somewhat inspired by taking the things I like about Apple Music and fb2k, but also fixing things I thought were dumb.

Full disclaimer: AI assisted coding was used. I have been building somewhat high quality software for a long time (decades) before AI existed, and I'd like to think the decisions I've been making reflect this as opposed to just vibing slop. I probably could have written it myself, but I kind of wanted to take a step back and be more of an architect/technical lead/product owner rather than a coder for this.

— @radiosilence

The pieces

Every part of kōan is the same Rust core with a different front on it. The apps link the core in-process; nothing between the interface and the audio engine is a network hop.

  • macOS app. SwiftUI, for the machine you listen at. Plays local folders, a server, or both merged into one library.
  • iOS app. The same SwiftUI app in a phone's shell. A phone has no music folder, so it plays from a server, and keeps what it has played in a local cache.
  • Terminal UI and CLI. koan on macOS and Linux: the player in a terminal, plus scanning, search, file organisation and the server itself.
  • Server. koan --headless, or the container image, on the machine that holds the music. It serves a web UI, share links, an OpenSubsonic API and MCP.

For a single computer with the music on it, the app on its own is enough. To listen from a phone, another computer or a browser, run the server where the music lives and point everything else at it. The apps sync its library, stream what they play and cache it, so a record played once plays again with no signal. Any Subsonic client works against it as well.

music ──► │ library · web UI · shares · MCP   │
          │ OpenSubsonic API                  │
          └──┬──────────┬──────────┬──────────┘
             │          │          │
         macOS app   iOS app   TUI · Play:Sub · …

Install

macOS app

Download Koan.dmg, open it and drag kōan into Applications. It is signed and notarised. Or with Homebrew:

brew install --cask radiosilence/koan/koan-app

You may have to update Homebrew's trust settings to trust the tap.

Requires macOS 26 or later.

iOS app

Not on the App Store or TestFlight yet. Build it from source with Xcode and install it on a phone plugged into the Mac, signed with your own (free) Apple developer team:

git clone https://github.com/radiosilence/koan.git && cd koan
just ios-phone

Requires iOS 26 or later, and a kōan, Navidrome or other Subsonic server to play from.

Command line and terminal UI

# mise (recommended)
mise use -g github:radiosilence/koan@latest

# homebrew
brew install radiosilence/koan/koan

# or via cargo
cargo install koan-cli

# or build from source
git clone https://github.com/radiosilence/koan.git && cd koan
cargo install --path crates/koan-cli

A single binary. macOS works out of the box with CoreAudio. Linux needs the ALSA and D-Bus development headers:

# Debian/Ubuntu
sudo apt install libasound2-dev libdbus-1-dev

# Fedora
sudo dnf install alsa-lib-devel dbus-devel

# Arch
sudo pacman -S alsa-lib dbus

Setting it up

One computer

In the macOS app, everything is in Settings: Library points kōan at your music and scans it, and playback, output device and radio have their own panes. No terminal is needed.

From the command line:

koan config init   # create the config dir and a commented template
# edit ~/.config/koan/config.local.toml:
#   [library]
#   folders = ["/path/to/your/music"]
koan scan          # index your library
koan               # launch the TUI

space pauses, < and > skip, p picks tracks, a picks albums, q quits.

A server for everything else

Run the container on the machine with the music. It needs no sound card, keeps its config, index and keys in /config, and only ever reads the library.

docker run -d --name koan -p 4000:4000 \
  -v koan-config:/config \
  -v /path/to/music:/music:ro \
  -e 'KOAN_LIBRARY__FOLDERS=["/music"]' \
  -e 'KOAN_GRAPHQL__ALLOWED_HOSTS=["music.example.com"]' \
  -e KOAN_SHARING__PUBLIC_URL=https://music.example.com \
  ghcr.io/radiosilence/koan:latest

docker exec -it koan koan auth setup       # signing keys and the admin account
docker exec -it koan koan subsonic setup   # turn on the Subsonic API

Put it behind a reverse proxy with TLS at the hostname you listed. The server refuses any Host it was not given, and share links are built on public_url. Add accounts for other people with koan auth create-user. Without a container, koan --headless --bind 0.0.0.0 does the same with the config in ~/.config/koan; the headless server guide has the details.

Then sign in from each client with a kōan account:

  • Browser: open the hostname.
  • macOS and iOS apps: Settings → Server.
  • Terminal: koan remote login https://music.example.com <user>, then koan remote sync.
  • Other Subsonic apps: the same URL and account.

A Navidrome or other Subsonic server works in the kōan server's place, for the apps and terminal UI; the web UI, share pages, linked apps and MCP are kōan's own. Local and remote tracks merge into one library, local files take priority for playback, and remote tracks stream while they download.

On Kubernetes

Each release publishes a Pulumi component at the same version, @radiosilence/koan-pulumi, on GitHub Packages. It builds the Deployment, its Services and a NetworkPolicy that admits only your ingress to the API and only your MCP gateway to MCP:

# .npmrc (GitHub Packages wants a token even for public packages)
@radiosilence:registry=https://npm.pkg.github.com
import { createKoan } from "@radiosilence/koan-pulumi";

createKoan(provider, "media", {
  hostname: "music.example.com",
  library: { hostPath: "/mnt/music" },
  state: { hostPath: "/var/lib/koan" },
  nodeSelector: { "kubernetes.io/hostname": "media-node" },
});

Route the hostname to the koan Service with whatever ingress you run. Pin the package version and the server follows it: the image tag is the package's version.

Filing new music

kōan reads tags as they are and does not rewrite them. sift, a separate tool, matches a download against MusicBrainz, tags it, embeds the cover and files it into the library, reading an existing beets config. A server watching that folder picks the album up on its own.

mise use -g github:radiosilence/sift
sift import ~/Downloads/some-album

What it does

Playback

  • Bit-perfect output through CoreAudio on macOS and ALSA on Linux. The device is switched to the source's sample rate rather than resampled to reach it; when a device refuses, the format badge says the output is resampled.
  • Gapless: the decoder runs ahead across track boundaries.
  • Formats: FLAC, MP3, AAC, Vorbis, Opus, ALAC, ADPCM, WAV, AIFF and CAF, in Ogg, Matroska/WebM and MP4 containers.
  • ReplayGain in track and album modes, with peak limiting and a configurable pre-amp.
  • Radio mode: endless play scored from your own library on acoustic similarity, genre, era and artist. It does not ask any outside service for recommendations.
  • Media keys and now-playing through Control Center on macOS and MPRIS on Linux.

Library

  • Local and Subsonic/Navidrome in one library, with incremental sync, streaming, and favourites and playlists synced both ways.
  • Search across the whole library with SQLite full-text search.
  • Queue grouped by album, with drag reordering, multi-select, 100 levels of undo, and Finder drag and drop. It survives restarts.
  • Playlists, ordered and named, exportable as M3U8.
  • Synced lyrics from LRCLIB, with the current line highlighted.
  • File organisation with foobar2000-compatible format strings (%field%, [conditionals] and 59 $functions()). Every move is previewed, collisions included, before anything is touched.

Automation

  • GraphQL API for full control alongside the app or TUI, or headless as a music server.
  • Subsonic-compatible API, so other Subsonic clients can play from a kōan server.
  • MCP server (koan mcp) exposing the player to Claude Desktop.
  • Accounts with Ed25519 JWTs, three roles and 1Password CLI integration.

Not there yet: tag editing, and DSP or EQ.

The macOS app

A SwiftUI app built for macOS 26. Browse and search the library (⌘K), build and reorder the queue, keep playlists, favourite tracks, albums and artists, read synced lyrics, look through play history and reorganise files on disk. First-run setup covers library folders and remote sign-in.

It links the Rust core in-process through FFI rather than talking to a server, so there is no daemon, port or auth surface between the interface and the audio engine, and CoreAudio output never leaves Rust. It shares one library and one config with the terminal UI: a queue saved in one shows up in the other.

Two things it leaves to the terminal: visualisers, and running the server (koan serve).

The iOS app

The macOS app's pages and engine in a phone's shell: a tab bar for the queue, the library, search and settings, and Now Playing with synced lyrics, radio and AirPlay over the playing record's colour. It plays from a server and caches what it plays, so the rest of an album or queue carries on underground. On an iPad with room for a sidebar it takes the Mac's layout. Output goes through the system mixer, so bit-perfect is a claim for the Mac and Linux only.

The terminal UI

A full-screen Ratatui interface that runs on macOS and Linux: a transport bar with album art, an album-grouped queue, a fuzzy picker, a library browser, a lyrics panel, mouse support and 22 visualiser modes.

As a server

Run kōan on the machine that holds the music (koan --headless, or a container) and it serves the library to everything else. It stands in for Navidrome rather than needing it.

  • Web UI. Albums, artists, search and a queue, laid out for a phone as well as a desktop. Sorting and filters live in the URL. Playback is gapless, in the browser.
  • Share links. Sharing a track shares its album, cued to that track. An album shares the album, and an artist their albums. The page plays without an account, and a pasted link unfurls with its cover.
  • OpenSubsonic API. Subsonic apps such as Play:Sub, and kōan's own app and terminal UI on other machines, connect with a kōan account: by password, by token auth or with an API key.
  • Accounts. Admin, user and read-only roles, and API keys that can be revoked from the web UI.
  • Linked apps. kōan's Mac and iPhone apps keep a connection open to a kōan server, which makes each one a remote the server can drive: see what it is playing and its queue, start an album on it, queue, pause and skip. Playlist edits and library changes reach every device without a sync, and one that is away receives them when it next connects. A plain Subsonic server can only answer what an app asks.
  • MCP. Over HTTP, behind a gateway that signs people in, so an assistant can browse the library and drive playback as that person, on any of their linked devices: "play this album on my phone", or a playlist that fills as the albums for it arrive.
